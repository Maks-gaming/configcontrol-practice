## Спецификация УВМ

| Операция | Имя в JSON | A | B | Размер |
|---|---|---:|---:|---:|
| Загрузка константы в аккумулятор | `load` | 5 | биты 3-19, константа | 3 байта |
| Чтение памяти по адресу в аккумуляторе | `read` | 3 | нет | 1 байт |
| Запись аккумулятора в память | `store` | 4 | биты 3-25, адрес | 4 байта |
| Унарный минус для аккумулятора | `neg` | 7 | нет | 1 байт |

## Язык ассемблера

Исходная программа является JSON-списком объектов. У каждого объекта есть
поле `op`. Для `load` и `store` также указывается целое неотрицательное
поле `arg`. Для `load` это константа от 0 до 131071, для `store` это адрес
от 0 до 8388607. У `read` и `neg` аргумента нет.

```json
[
  {"op": "load", "arg": 269},
  {"op": "read"},
  {"op": "store", "arg": 892},
  {"op": "neg"}
]
```

Файл `examples/spec.json` содержит все команды и тестовые значения из
спецификации варианта.

## Запуск ассемблера

Нужен Python 3, сторонние библиотеки не используются.

```sh
./run.sh examples/spec.json out/spec.bin --test
```

В Windows:

```bat
run.bat examples\spec.json out\spec.bin --test
```

Тестовый режим выводит внутреннее представление с полями A и B:

```text
1. load: A=5, B=269
2. read: A=3
3. store: A=4, B=892
4. neg: A=7
0x6D, 0x08, 0x00
0x03
0xE4, 0x1B, 0x00, 0x00
0x07
```

Байтовые строки полностью совпадают с тестами спецификации. Обычный запуск
без `--test` создает двоичный файл и выводит только число команд и его путь.
Для повторения демонстрации выполните `sh scripts/stage2.sh`.

## Интерпретатор и дамп памяти

Интерпретатор принимает двоичную программу, путь к JSON-дампу и границы
диапазона адресов. Границы входят в дамп. Память команд хранится отдельно
от памяти данных. Незаписанные ячейки выбранного диапазона выводятся с
нулевым значением, а чтение неинициализированной памяти считается ошибкой.

```sh
./run.sh examples/copy.json out/copy.bin
python3 -m src.interpreter out/copy.bin out/copy-dump.json 20 32
```

В Windows вместо второй команды:

```bat
py -3 -m src.interpreter out\copy.bin out\copy-dump.json 20 32
```

Пример `examples/copy.json` записывает массив `[11, 22, 33]` по адресам
20-22 и копирует его на адреса 30-32. После выполнения источник не меняется:

```json
{"20": 11, "21": 22, "22": 33, "30": 11, "31": 22, "32": 33}
```

Здесь для краткости пропущены нулевые адреса 23-29. Полный дамп находится
в `out/copy-dump.json`. Демонстрация повторяется командой
`sh scripts/stage3.sh`.

## Тесты

```sh
python3 -m unittest discover -s tests -v
sh scripts/stage1.sh
sh scripts/stage2.sh
sh scripts/stage3.sh
```

Проверяются значения полей всех четырех команд, точные байтовые
последовательности из спецификации, запись двоичного файла, формат
внутреннего представления, декодирование, команды `load`, `read`, `store`,
копирование массива, JSON-дамп и обработка ошибок исходной программы и
машинного кода.
