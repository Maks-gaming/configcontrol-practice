# ДКР по конфигурационному управлению, вариант 16

Транслятор учебного конфигурационного языка в XML. Программа читает текст из
стандартного ввода и записывает результат в стандартный вывод. Для синтаксического
разбора используется специализированная библиотека `pyparsing`, а не ручной разбор
строк.

## Возможности

- целые числа со знаком: `10`, `+25`, `-7`;
- строки в двойных кавычках, включая Unicode: `"Пример строки"`;
- массивы с любой вложенностью: `[1 "text" [2 3]]`;
- объявление констант: `(def name 42)`;
- постфиксные выражения: `#(name 1 +)`;
- операции `+`, `-`, `mod()` и `abs()`;
- выражения внутри массивов и других выражений;
- сообщения о синтаксических и вычислительных ошибках с ненулевым кодом выхода.

Имена констант состоят только из латинских букв и учитывают регистр. Константу
можно использовать после её объявления. Повторное объявление запрещено. Внутри
массива значение константы получают выражением, например `#(name)`.

## Синтаксис

```text
число       = [+-]?\d+
имя         = [a-zA-Z]+
строка      = "текст"
значение    = число | строка | массив | выражение
массив      = [ значение ... ]
объявление  = (def имя значение)
выражение   = #( операнд или операция ... )
```

Операндами выражения являются числа, имена объявленных констант и вложенные
выражения. Операции записываются после операндов:

```text
#(a b +)          сложение
#(a b -)          вычитание
#(a b mod())      остаток от деления a на b
#(a abs())        модуль числа a
```

Арифметические операции принимают только числа. После вычисления в стеке должно
остаться одно значение. Для `mod()` используется операция остатка Python `%`.
Деление на ноль выдаёт ошибку.

## Формат XML

Корневым элементом всегда является `config`. Тип значения записывается в атрибуте
`type`. Элементы массива называются `item`, а объявление константы сохраняет имя в
атрибуте `name`.

Вход:

```text
(def base 10)
["result" #(base 5 +) [#(base 3 mod())]]
```

Выход:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<config>
  <constant name="base" type="number">10</constant>
  <value type="array">
    <item type="string">result</item>
    <item type="number">15</item>
    <item type="array">
      <item type="number">1</item>
    </item>
  </value>
</config>
```

## Установка и запуск

Нужны Python 3.9 или новее и `pyparsing` 3.x. Сборка не требуется, достаточно
установить зависимость:

```sh
python3 -m venv .venv
. .venv/bin/activate
python3 -m pip install -r requirements.txt
```

Запуск в Linux:

```sh
./run.sh < examples/server.cfg
```

Запуск в Windows:

```bat
run.bat < examples\server.cfg
```

Можно запустить модуль напрямую:

```sh
python3 src/main.py < examples/server.cfg > result.xml
```

Параметров командной строки и настроек окружения нет. Вход всегда читается из
`stdin`, XML выводится в `stdout`, ошибки выводятся в `stderr`. Код завершения `0`
означает успех, код `1` означает ошибку входного текста или вычисления.

## Запуск тестов

```sh
python3 -m unittest discover -s tests -v
```

Тесты используют только стандартный `unittest`. Проверяются все типы значений,
вложенные массивы и выражения, четыре операции, порядок объявления констант,
неправильный синтаксис, вычислительные ошибки, потоки CLI и все три примера.

## Примеры из разных предметных областей

В каталоге `examples` находятся исходники и ожидаемые XML-файлы:

1. `server.cfg` и `server.xml`: настройки сетевого сервера, порты и очередь.
2. `study.cfg` и `study.xml`: учебная группа, курс и результаты занятий.
3. `robot.cfg` и `robot.xml`: маршрут и параметры двух моторов робота.

Команда проверки любого примера:

```sh
./run.sh < examples/robot.cfg
```

## Описание функций

| Функция | Назначение |
|---|---|
| `build_parser()` | Создаёт грамматику языка средствами `pyparsing`. |
| `require_number()` | Проверяет числовой тип операнда. |
| `apply_binary()` | Выполняет `+`, `-` или `mod()`. |
| `take_operands()` | Извлекает операнды из стека и проверяет их количество. |
| `evaluate_expression()` | Вычисляет постфиксное выражение на стеке. |
| `evaluate_value()` | Вычисляет выражения в значении и вложенных массивах. |
| `add_xml_value()` | Создаёт XML-элемент с типом и содержимым значения. |
| `translate()` | Выполняет разбор, вычисления и возвращает XML-строку. |
| `main()` | Связывает транслятор со `stdin`, `stdout` и `stderr`. |

Класс `Definition` хранит объявление константы, класс `Expression` хранит элементы
постфиксного выражения. Исключение `LanguageError` объединяет понятные пользователю
ошибки языка.

## Ответы по пунктам задания

- Входной текст принимается из стандартного ввода, результат на языке XML выводится
  в стандартный вывод. Это реализовано в `src/main.py`.
- Синтаксические ошибки выявляет `pyparsing`. Транслятор добавляет номер строки и
  столбца, печатает сообщение в `stderr` и завершается с кодом `1`.
- Числа, строки, имена и массивы разбираются по правилам варианта 16. Массивы и
  выражения могут быть вложенными.
- Объявление `(def имя значение)` вычисляется на этапе трансляции. Значение сразу
  сохраняется в таблице констант и также попадает в XML.
- Выражение `#(...)` вычисляется на стеке. Реализованы сложение, вычитание, `mod()`
  и `abs()`. Результат становится обычным значением и может находиться в массиве,
  константе или другом выражении.
- Все конструкции и их вложенность покрыты тестами в `tests/test_config_language.py`.
- Три примера из разных предметных областей находятся в каталоге `examples` вместе
  с ожидаемыми результатами.
